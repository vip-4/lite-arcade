关于 Lite Arcade 与 GEO 优化

一句话摘要

Lite Arcade 是一个零依赖的静态开源游戏站：全部页面由 deploy/build.ps1 从 src/ 与 config/ 生成到 dist/，不引入任何打包工具或运行时；同时按 SEO 与 GEO 两套标准输出机器可读内容，包括 sitemap.xml、robots.txt（含 AI 爬虫白名单）、llms.txt、llms-full.txt，以及 VideoGame / FAQPage / HowTo / ItemList / BreadcrumbList 结构化数据。

GEO

什么是 GEO（生成式引擎优化）

GEO（Generative Engine Optimization）指让站点更容易被 ChatGPT、Perplexity、Claude、Google AI Overviews 等生成式引擎检索、理解并在回答中引用。它与传统 SEO 的区别在于：目标不只是“排名”，而是“被引用”。

GEO 与 SEO 的差异

维度SEOGEO
目标搜索结果排名被生成式答案引用
关键信号关键词、外链、Core Web Vitals事实密度、可引用性、实体一致性
内容形态面向关键词的长文答案前置、FAQ、结构化事实清单
抓取方搜索引擎爬虫GPTBot、ClaudeBot、PerplexityBot 等

本站已实现的 GEO 措施

  • llms.txt / llms-full.txt：为大模型提供站点摘要、事实清单与页面索引。
  • AI 爬虫白名单：robots.txt 显式放行 GPTBot、OAI-SearchBot、ClaudeBot、PerplexityBot、Google-Extended 等。
  • 答案前置段落：每页首屏给出 40–60 字的定义式回答，便于直接摘取。
  • 结构化数据：VideoGame、HowTo、FAQPage、ItemList、BreadcrumbList、SpeakableSpecification。
  • 稳定锚点：#answer、#faq、#catalog 等 ID 长期不变，便于深度引用。
  • 实体一致性：站名、许可、技术形态在各页表述统一。
  • 可核实性：目录数据标注采集来源与快照时间，不编造评分与评价。
  • 性能：零外部请求、系统字体、无阻塞脚本，利于抓取与体验。
资产流水线

Blender MCP 3D 资产流水线

站内视觉目前全部由 CSS 与 Canvas 绘制，不依赖任何图片资源。若要用 3D 渲染替换首屏视觉，可接入 Blender MCP（Model Context Protocol 服务端，把 Blender 暴露给 AI 调用）。

  1. 在 Blender 中启用 Blender MCP 插件与其服务端，确认本地监听端口可用。
  2. 通过 MCP 工具执行场景构建与材质调整，输出渲染图到约定目录。
  3. 把渲染结果导出为 assets/img/og-cover.png（1200×630）与 assets/img/hero.webp。
  4. 重新执行 deploy/build.ps1，构建脚本会一并校验内链与资源是否存在。

部署

本地生产化部署配置

构建产物是纯静态文件，可托管在任意 HTTP 服务器或 CDN。仓库已内置四种部署形态。

形态配置文件启动方式
本地静态服务deploy/serve.ps1.\deploy\serve.ps1 -Root dist -Port 8080
Docker + nginxdeploy/Dockerfile、deploy/nginx.confdocker build -f deploy/Dockerfile -t lite-arcade . && docker run -p 8080:8080 lite-arcade
Netlifydeploy/netlify.toml绑定仓库，构建命令 pwsh ./deploy/build.ps1，发布目录 dist
Verceldeploy/vercel.json导入项目，自动识别 outputDirectory = dist
生产环境请把 config/site.json 中的 baseUrl 换成真实域名，或用 .\deploy\build.ps1 -BaseUrl "https://your-domain.com" 覆盖；canonical、og:url 与 sitemap 会自动同步。
